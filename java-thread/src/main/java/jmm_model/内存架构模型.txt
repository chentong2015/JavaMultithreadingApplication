Java Memory Model 内存模型
屏蔽各种硬件和OS的内存访问差异，让java程序在各个平台都能达到一致的内存访问效果
线程的创建和切换比较耗费资源，会涉及到从用户态到内核态的切换

TODO. 线程在运行时CPU中缓存一致性
1. 缓存一致性协议(MESI): 不同硬件级别不同实现
   多个cpu从主内存读取同一个数据到各自的高速缓存，当其中某个cpu修改缓存中数据，该数据会同步回主内存
   其他cpu通过"CPU总线嗅探机制"感知到数据的变化从而将自己缓存里的数据失效
   将工作内存中缓存值置于invalid状态，之后CPU再次读取使用的时候，发现已经失效，重新read->load再运行
2. 总线嗅探机制: 线程"监听"总线这个"消息队列"，嗅探共享的变量
3. 缓存加锁: 缓存锁基于缓存一致性协议来实现，一个处理器的缓存回写到内存会导致其他处理器的缓存无效
